Why this post exists

When people talk about foundation models, they often mean the model weights themselves. But a model is more than just weights; This post explains what each of those components are and why they matter.

What is a model?

Models are an abstraction of a process. I wrote a blog about 7 years ago (which is so old it has lost its images, yikes) centered around the George Box quote “Essentially, all models are wrong, but some are useful” that I think captures this concept pretty well.

Models are not the thing themselves; they are a representation. I like starting here because it grounds us in the idea that a model is a representation — and for machine learning models, this is captured as a mathematical function and a set of weights (numbers) that best approximate the underlying relationship between input and output.

In its most simple form, a model can be represented by a function (a mathematical equation) that takes an input and produces an output. For example, a linear regression model can be represented by the equation:

\[ y = \beta_0 + \beta_1 x_1 \]

The model’s weights (the \(\beta\) values, also known as coefficients) are learned from data, and they determine how the input features (\(x\) values) are combined to produce the output (\(y\) value). So when we “ship” a linear regression, we are shipping the function and the learned weights, which together define the model’s behavior.

The mathematical functions attempt to capture the transformation from input to output by making assumptions about the shape of the transformation and the relationships between variables. We then “learn” the optimal values for these parameters from data, using patterns in the data to “fit” the model.

The components of a foundation model

Like a linear regression, a foundation model is a package, not a single thing. It contains several components that work together to process input and generate output. When you “ship” a foundation model, you are shipping all of these components together, which together define the model’s behavior. You can see all of these components in the Mistral-Large-4-1T-A52B model card.

The two main components are the weights, which are the learned parameters of the model, and the architecture, which defines how the model processes information. The weights are like the coefficients in a linear regression, while the architecture is like the structure of the equation itself.

  • Architecture: The structure of the model, which defines how information flows through the model and how the weights are applied. This includes the number of layers, the types of layers (e.g., attention, feedforward), and how they are connected. This is typically stored in a JSON format. The file extension for the architecture is typically .json.

  • Weights: The learned parameters of the model that capture the relationships between input and output. These are split across many files, each containing a portion of the model’s parameters. The file extensions are typically .bin, .pt, or .safetensors, depending on the framework used to train the model (e.g., PyTorch, TensorFlow).

Because foundation models are complex, they also contain additional components that help manage the model’s behavior and performance. These include a configuration file that specifies hyperparameters and other settings for the model, and a tokenizer that converts input text into a format that the model can process.

  • Configuration file(s): A file that specifies hyperparameters and other settings for the model. This is typically stored in a JSON format and contains information such as the model’s vocabulary size, maximum sequence length, and other hyperparameters that affect how the model processes input.

  • Tokenizer: A component that converts input text into tokens — pieces of text that have been converted into numerical representations the model can understand. The tokenizer converts input text into tokens and converts the model’s output tokens back into human-readable text. It is an essential component, as it bridges human language and the model’s numerical world.

The Executable Model in Memory

A Runtime Loader assembles these components into an executable model in memory, which can then be used to process input and generate output. The assembly work includes parsing the metadata, loading the weights into memory, applying the configuration settings, and preparing the model for inference. The loader also handles any necessary preprocessing of the input data, such as tokenization, and postprocessing of the output data, such as detokenization.

When a model is loaded into memory, it becomes an executable model. This means that the model’s weights and architecture are loaded into RAM, allowing it to process input and generate output. The executable model is what the serving runtime interacts with when it receives a request to generate output.

What gets Loaded into GPU Memory?

When a model is loaded into GPU memory, the weights and architecture are loaded into the GPU’s RAM, allowing it to process input and generate output. The executable model is what the serving runtime interacts with when it receives a request to generate output.

Weights are static once loaded — quantization and sharding change the footprint of the weights, but they are not changed during inference. The architecture is also static once loaded, as it defines how the model processes information and applies the weights.

Temporary workspace is activations, attention GEMM buffers during execution. This is where the model stores intermediate results and temporary data during inference. The workspace is allocated in GPU memory and is used to store activations, attention matrices, and other temporary data that is needed for the model to process input and generate output. The size of the workspace can vary depending on the model architecture, the input size, and the batch size.

Overhead is the additional memory used by the model for things like the tokenizer, configuration settings, and other metadata. This overhead is typically small compared to the size of the weights and architecture, but it can still be significant for large models.
